# Навык: Политика ключей (безопасный вынос) — модуль M·MAKE

**Главный принцип:** ключ **не живёт в коде и не пишется в чат**. Агент делает **пустые заготовки** (`.env.example`), реальные значения человек вставляет **сам** — в защищённое поле (Supabase secrets / Vercel / поле сервиса), мимо репозитория.

---

## 🗺️ Карта «какой ключ куда»

| Ключ | Тип | Куда | Во фронт / в git? |
|---|---|---|---|
| **Supabase anon** | публичный | фронт `.env` (`VITE_...`), Vercel env | **Да — но безопасен только при включённом RLS** |
| **Supabase service_role** | секретный (обходит RLS) | только сервер / Edge Function | **Никогда** |
| **OpenAI key** | секретный | только сервер: Edge Function secrets | **Никогда** |
| прочие (платёжка и т.п.) | секретный | сервер / Edge Function / Vercel Sensitive | **Никогда** |

> Связка «anon key во фронте + RLS выключен» = катастрофа (реальные утечки: Moltbook — 1,5 млн ключей; CVE-2025-48757). Anon-ключ и RLS учим одним блоком.

---

## 🧰 Куда класть секреты

- **Supabase Edge Function secrets:** `supabase secrets set OPENAI_API_KEY=...` (или `--env-file`). В функции — `Deno.env.get('OPENAI_API_KEY')`. Файл `supabase/functions/.env` — в `.gitignore`.
- **`.env` + `.gitignore`:** базовая гигиена всегда (`.env`, `.env.local`, `supabase/functions/.env`).
- **Vercel:** Settings → Environment Variables. Публичные — с префиксом `VITE_`; секретные — тумблер **Sensitive** (значение потом не прочитать).
- **VPS:** `.env` на сервере вне git-дерева, `chmod 600`, не логировать.

**GitHub (факт):** у публичных репо push protection **блокирует** пуш с распознанным секретом. НО у приватных бесплатных репо — не блокирует, и ловятся только **известные форматы** → `.env` + `.gitignore` обязательны в любом случае, на GitHub не полагаться.

## 🤝 Проводник — готовые промпты (веди за руку, ключ в чат не проси)

1. **Заготовки:** «Создай `.env.example` с ПУСТЫМИ полями (`VITE_SUPABASE_URL=`, `VITE_SUPABASE_ANON_KEY=`). Создай `.gitignore` с `.env`, `.env.local`, `supabase/functions/.env`. Значения впишу сам, тебе не показываю.»
2. **Секретный ключ на сервер:** «Edge Function читает ключ ТОЛЬКО через `Deno.env.get('OPENAI_API_KEY')`, нигде не хардкодь и в чат не проси. Дай мне одну команду `supabase secrets set OPENAI_API_KEY=...`, я выполню сам.»
3. **Само-аудит перед пушем:** «Просканируй проект: нет ли захардкоженных ключей/токенов/`service_role` во фронте или в файлах, что попадут в git. Проверь, что `.env` и `supabase/functions/.env` в `.gitignore`. Покажи `git status`, подтверди, что секретов нет. Значения ключей в ответ не выводи.»
4. **Vercel:** «Дай пошагово по кликам, как добавить в Vercel: `VITE_SUPABASE_ANON_KEY` как обычную, секретные — с тумблером Sensitive. Значения введу сам.»

## 🔑 5 правил простым языком
1. **Публичный ключ — можно в браузер, секретный — только на сервер** (anon ок при включённом RLS; service_role и OpenAI — никогда во фронт/git).
2. **Ключ живёт в защищённом хранилище, не в коде** (Supabase secrets / Vercel Sensitive / VPS `.env` chmod 600).
3. **`.env` всегда в `.gitignore`; агенту — только `.env.example` пустой.**
4. **GitHub подстрахует, но не заменит гигиену** (публичные репо блокируют, приватные бесплатные — нет).
5. **Утёк — перевыпусти (rotate),** не просто удали.

## ✅ Определение готовности
Ни одного ключа в коде/чате; `.env` в `.gitignore`; секреты в Edge Function secrets / Vercel Sensitive; само-аудит перед пушем чист.
