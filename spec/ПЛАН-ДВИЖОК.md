## Что достраиваем (трубы)
1. **Активация подписки**: пользователь жмёт кнопку PayPal (на Source.jsx, там же где купон) → PayPal Subscribe (JS SDK) → approval → сервер подтверждает → `profiles`: `plan='subscription'`, `subscription_status='active'`, `paypal_subscription_id`, `subscription_current_period_end`.
2. **Продление / сбой платежа**: PayPal шлёт вебхук на каждый цикл списания → сервер продлевает `subscription_current_period_end` при успехе, ставит `subscription_status='past_due'` при неудаче (доступ пока держится до текущего `period_end`).
3. **Отмена**: пользователь отменяет **в своём кабинете PayPal** (не в приложении) → вебхук `BILLING.SUBSCRIPTION.CANCELLED` → `subscription_status='canceled'`, `period_end` не трогаем — доступ гаснет сам собой, когда дата пройдёт.
4. **Купоны — досдать начатое**: применить миграцию на живую БД, закоммитить готовый код.
5. **Выдача новых купонов**: экран `/admin` — форма «код, вид (безлимит / N раз), число раз, заметка» → создаёт строку в `coupons`. Виден и доступен только владельцу (проверка email на сервере, не в коде и не в клиенте).

## Поверхность
Экран: тот же `Source.jsx`, где сейчас купон — кнопка PayPal ставится рядом с полем купона. Статус — существующий бейдж в `AppLayout.jsx` (текст расширяется: активна / отменена, но доступ до даты / просрочен платёж).

## Данные
Одна миграция (или расширение ещё не применённой):
- `profiles.plan` / `credits_remaining` / `subscription_status` / `paypal_subscription_id` — уже в `20260729_coupons_and_credits.sql`
- **новое поле**: `profiles.subscription_current_period_end timestamptz`

`hasAccess()` меняется на проверку по дате:
`есть period_end AND now() < period_end` → доступ по подписке (это покрывает и «active», и «canceled, но период ещё не кончился»). Купон/трайл-логика по `credits_remaining` — без изменений.
